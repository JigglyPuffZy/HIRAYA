# HIRAYA Backend

Python FastAPI backend for heat stroke risk prediction. Trains and serves **Random Forest**, **XGBoost**, and **LightGBM** models, then selects a champion model for inference.

## Supabase (production database + auth)

See [`../supabase/README.md`](../supabase/README.md) for full setup.

1. Create a Supabase project
2. Run `supabase/migrations/001_initial_schema.sql` in the SQL Editor
3. Copy keys into `backend/.env` and the mobile `.env`
4. Mobile auth uses Supabase; the backend verifies Supabase JWT tokens

## Quick start

```powershell
cd backend
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
copy .env from your project setup (see `../supabase/README.md` for keys)

# Train models (uses data/heatstroke_training_data.csv + health-condition augmentation)
python scripts/train_model.py

# Start API
uvicorn app.main:app --reload --host 0.0.0.0 --port 8000
```

The ML pipeline now includes **binary health-condition features** (`asthma`, `hypertension`, `heart_disease`, `diabetes`, `kidney_disease`, `copd`, `obesity`, `other_chronic`). Re-run training after pulling these changes so `models/champion.joblib` matches the new feature set.

Mobile predictions combine:
- **ML model** — environmental + vitals + health-condition features
- **On-device decision tree** — PAGASA heat index + personalized vulnerability
- **Rule engine** — condition-specific safety tips (not generated by ML)

Health check: `GET http://127.0.0.1:8000/health`

## Mobile app connection

1. Start the backend on your PC (`--host 0.0.0.0`).
2. Set in the Expo app `.env`:
   ```
   EXPO_PUBLIC_API_URL=http://<your-lan-ip>:8000
   ```
3. Optional: set `OPENWEATHER_API_KEY` in `backend/.env` so weather is proxied through the backend when logged in.

## API endpoints

| Method | Path | Auth | Description |
|--------|------|------|-------------|
| POST | `/auth/register` | No | Create account |
| POST | `/auth/login` | No | Sign in |
| GET | `/auth/profile` | Yes | Current user |
| POST | `/predictions/heat-risk` | Yes | Run ML prediction + save history |
| GET | `/assessments/history` | Yes | List past assessments |
| GET | `/assessments/{id}` | Yes | Assessment detail |
| POST | `/weather/current` | Yes | Weather proxy (OpenWeather) |

## ML pipeline

- **Dataset:** `data/heatstroke_training_data.csv` (public heatstroke training data)
- **Features:** age, sleep, breakfast, vitals, activity, hydration + weather
- **Target:** heatstroke (yes/no) → probability score
- **Risk levels:** LOW / MODERATE / HIGH / EXTREME (from probability thresholds)
- **Artifacts:** `models/champion.joblib`, `models/manifest.json`

Re-train after dataset updates:

```powershell
python scripts/train_model.py
```

## Notes

This is a research support system, not a medical diagnostic device. Thresholds and labels should be validated against the approved HIRAYA methodology before production use.
